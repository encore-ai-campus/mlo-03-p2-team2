# 02 위반유형 팀원 통합 공유 스키마 초안

작업 워크트리 `C:\mlo-03-p2-team2`, 브랜치 `codex/domain-02-sharing-ai-ready`. 02가 03 반복 위반과 05 지역 분석에 제공할 데이터 계약 제안입니다. [05 검토용 샘플과 검증 기록](team_sharing_sample.md)을 생성했습니다. 정식 배포와 소비 코드 전환은 팀 합의 후 진행합니다.

| 제공 파일 제안 | 한 행의 의미와 키 | 필수 컬럼 |
| --- | --- | --- |
| `02_inspection_violation_codes.parquet` | 한 점검에서 관측한 고유 위반 코드 한 건. 키는 `(inspection_key, code_system_version, violation_cd)` | 세 키 모두 문자열, NULL 불가 |
| `02_inspection_violation_observations.parquet` | 위반 원문 및 파싱 결과가 어떠했는지를 나타내는 점검 1건. 키는 `inspection_key` | 점검 키와 `violation_observation_status`는 문자열, NULL 불가 |

공용 `inspection_key`는 01 점검 Silver의 값을 기준으로 대조합니다. 원천 점검 해시와 `source_row_num`이 같은지 확인한 뒤 같은 원천의 02 정상·격리 결과를 연결합니다. `violation_cd`는 02 정상 Silver의 문자열 코드를 사용합니다. 같은 점검·버전에서 반복된 코드가 여러 번 나와도 한 행으로 만듭니다. 코드 설명과 코멘트 원문은 02 상세 테이블에서 조회합니다.

| 값 | 초안의 판정 기준 |
| --- | --- |
| `raw_missing` | 원문이 NULL이거나 공백뿐인 점검. 코드 목록에는 행 없음 |
| `parsed` | 승인 조각이 하나 이상 있고 격리 조각이 없는 점검 |
| `partial` | 승인 조각과 격리 조각이 함께 있는 점검. 확인된 승인 코드만 제공 |
| `unrecognized` | 원문이 있고 승인 조각이 없는 점검. 코드 목록에는 행 없음 |

코드 체계 버전 후보는 05 현재 코드와 동일하게 2018-07-01 이전 `pre_2018_07_01`, 당일부터 `from_2018_07_01`입니다. 공용 날짜를 확인할 수 없는 점검은 관측 상태에는 남기고, 버전이 필요한 코드 테이블에는 넣지 않습니다. 이 제외 건수는 공유 기록에 남깁니다.

공유 시 한 실행에서 나온 파일들을 함께 제공하고, 실행 경로 또는 배치 ID, 원천 SHA-256, 스키마 버전, 파일별 행 수와 SHA-256을 기록합니다. 공용 점검 키마다 관측 상태 한 행, 코드 키 중복과 고아 참조 0건, 코드 버전과 점검일 일치, 전체 관측 상태 건수와 공용 점검 행 수 일치를 검증합니다.

03의 현재 실행은 정상·격리 상세와 대사 보고서를 읽습니다. 새 파일로 전환할 때는 `raw_missing → missing`, `unrecognized → unparsed`라는 상태 매핑과 반복 위반 분모를 합의해야 합니다. 05의 현재 입력 파일명은 `02_` 접두사가 없는 두 파일입니다. 접두사가 필요한 저장소 파일명과 소비 경로를 맞추는 방식은 05와 결정합니다.

첫 비교는 기존 02 승인 조각만 사용합니다. 코멘트 구분자가 없어 02에서 격리한 코드까지 인정할지, 03의 재발 비교와 05의 기록 건수에서 `partial`을 어떤 분모에 넣을지는 팀 결정으로 남깁니다. `raw_missing`과 `unrecognized`는 위반 0건을 뜻하지 않습니다.

점검 이전에 사용할 위반 이력 피처와 팀 결정 항목은 [AI Ready 피처 후보 초안](ai_ready_feature_draft.md)에 정리했습니다.
