# 계층별 역할과 변환 규칙 초안

측정 근거: [원천 프로파일](source_profiles.md)과 [기계 판독 결과](source_profiles.json). 아래 Silver·Gold 규칙은 **예정**이며 현재 구현되지 않았다. `검토 필요`는 데이터 의미나 처리 기준을 팀에서 결정해야 함을 뜻한다. 측정 기준과 업무 규칙을 혼동하지 않는다.

## 계층의 책임

| 계층 | 역할 | 현재 상태 |
| --- | --- | --- |
| Origin | 시카고시 다운로드 스냅샷과 메타데이터·체크섬을 원본 그대로 보관 | 보관 중 |
| Bronze | 원천 행·문자열·geometry를 보존하고 출처·적재 시각만 추가 | 구현됨 |
| Silver | 원본과 정제값을 추적하며 형식·키·범주를 표준화하고 예외를 기록 | 미구현 |
| Gold | 검증된 Silver에서 grain이 명확한 사실·차원·관점별 모델 구성 | 미구현 |

## 팀 공통 STD 규칙과의 대조 (2026-11-20)

팀원 초안의 출처, 65개 컬럼 매핑, 타입 충돌, 코드 검토 상태는 [표준안 대조](standards/team_standard_review.md)와 [컬럼 매핑](standards/column_mapping_review.csv)에 기록했다. 아래는 **Silver 구현 예정 규칙**이며 팀 초안의 검증·합의가 끝난 확정 규칙이 아니다. 기존 SI 규칙과 측정 결과는 위 표에 그대로 유지한다.

| 팀 규칙 | 기존 규칙과 연결 | 검토한 적용안 | 검증 기준 | 상태 |
| --- | --- | --- | --- | --- |
| STD-01 컬럼명 | SI-005~008 | 데이터셋+원천 컬럼으로 표준명을 조회하고 `snake_case`로 매핑; 충돌 시 자동 덮어쓰기 금지 | 65개 매핑의 일대일 범위와 동일 테이블 내 이름 중복 검사 | 예정·검토 필요 |
| STD-02 공백·결측 | SI-001, SI-009 | 원본 문자열을 보존하면서 일반 텍스트의 양끝 공백과 공란을 별도 표준값으로 관리; `Violations` 원문 내부 줄바꿈 보존 | 빈 문자열·공백 문자열·NULL형 문자 각각의 전후 건수와 원본 복원 | 예정·검토 필요 |
| STD-03 식별자·코드 | SI-005~006 | ID·ZIP·코드를 문자열로 유지; 점검 `License #`의 `0`·`9999999`를 무효로 보는 팀 제안은 원문 보존·건수 확인 후 결정 | 선행 0 보존, 유일성, sentinel 건수와 무매칭 영향 | 예정·검토 필요 |
| STD-04 숫자 | SI-002, SI-007~008 | 지역 번호 `int64`, 좌표·경계 수치 `float64` 후보; 파싱 실패와 업무 범위 위반을 분리 | 원문과 변환값 대조, 실패·범위 밖 건수, 정밀도 영향 | 예정·검토 필요 |
| STD-05 날짜·시각 | SI-003, SI-006 | CSV `MM/DD/YYYY` → `date32` 후보, 표시는 `YYYY-MM-DD`; UTC 시스템 시각은 별도 timestamp 후보 | 파싱/업무 유효성 분리, 특이 연도·기간 역전·시간대 검사 | 예정·검토 필요 |
| STD-06 범주 코드 | SI-001, SI-009 | `raw_value`, `mapped_code`, `mapping_status`를 분리; 등록 검토 중과 미등록을 구별 | 원천 범주 분포, 코드표 범위, 미등록·검토 건수 | 예정·검토 필요 |

팀 기준안의 `source_row_num`은 현 Bronze의 `_SRC_FILE`, `_LOAD_DTM`에 없는 컬럼이다. 이번 작업에서 Bronze를 변경하지 않는다. Silver 추적 방식과 원천 행 순번의 안정성을 팀과 합의해야 한다. 날짜·코드·JOIN의 세부 예외는 [통합 검토](standards/integration_review.md)에 기록한다.
